# Design a graphic

Resolve repository paths from this skill's location. Read `AGENTS.md`, `brand/BRAND.md`, the content brief and relevant positioning, audience and voice pages. When present, read `brand/patterns.md` and central tokens; inspect the relevant implemented composition and rendered reference. The active kit supplies identity, not a compulsory layout. Missing or stub context supplies no author facts or approved brand.

Establish the information relationship before choosing a composition: a thesis, sequence, comparison, hierarchy, evidence or reflection. Keep the copy faithful to its source. A missing number or screenshot is not permission to invent one.

Use dimensions from the requested destination or supplied brief. Verify current platform requirements when exact compliance matters. Infer routine layout details; ask only when a missing choice changes the content or format materially.

## Visual choices

Use approved brand rules when available. Otherwise create a plain unbranded draft when that fits the request: no invented logo, author signature, corporate palette, decorative footer or mandatory CTA. Mark temporary visual choices as draft choices rather than new brand policy.

Read [composition.md](references/composition.md) when designing an implementation explainer, exploring a richer direction or fixing work described as simplistic. Establish a focal point and an information-specific silhouette. Use concrete artifacts, expressive proportions and intentional detail; adding cards or effects alone does not improve craft. Keep authentic product screenshots intact and use supplied photography with known permissions.

When a reference repository is supplied, inspect both its instructions and at least one relevant implementation/export. Record the transferable mechanism and where it applies. Do not inherit the other author's colours, fonts, personal imagery, claims or CTA policy. Improve this client's identity through consistent visual roles and recognisable treatments, not a different style for each asset.

For carousels, give each page a specific job and maintain continuity. Include a call to action only when the brief provides a useful next step.

## Build and inspect

Choose tools actually available in the environment. HTML/CSS or SVG works for exact text and diagrams; an image-generation tool is useful for suitable illustration work. Use `flowchart` for editable process maps. Check the repo's renderer and dependencies before building new tooling.

For GIFs, looping graphics or a dynamic twin, read [motion-and-export.md](references/motion-and-export.md). Design the meaningful static composition first, then the object's action, reading hold and reset. Render actual GIF bytes when a GIF is requested. Deliver an MP4 companion and readable PNG where the environment supports them; an HTML animation alone is not a GIF export.

Keep working assets in `output/<asset-name>/` or the user-selected destination. Save editable source alongside the export. Use local or licensed fonts and verify actual font loading when rendering.

Inspect the rendered asset at its intended size and a small viewing size. Check text accuracy, hierarchy, clipping, contrast, connector collisions and missing assets. For animation, inspect opening, transition, result and loop seam, and check encoded playback as well as source frames. Use the craft questions in the composition reference separately from technical export checks. Fix visible defects and rerender. If rendering or inspection is unavailable, deliver the source and state the exact unverified step.

Return file links, dimensions and relevant limitations. Producing one graphic does not authorize changing shared brand rules or publishing it.
